# Scheduled Tasks

Settings → Scheduled Tasks replaces Database. The old `/settings/database` URL remains compatible. Connected-server cache controls are retained below the tasks.

Tasks are predefined and schedules are disabled by default. Each task supports Run now (Data Cleanup first offers Review cleanup), an interval of 1–365 days, saved configuration, and a last-run result. The scheduler checks once a minute while PosterView runs and catches up overdue enabled tasks after restart. Configuration and last-run results are stored in the application database. Tasks execute sequentially; failed runs are recorded and retry at the next interval.

- Data Cleanup: selected unused managed artwork, old local artwork mirrors, and abandoned temporary files, after the retention period (default 30 days). Managed artwork starts its grace period when cleanup first detects it as unreferenced; references becoming active again reset that grace period. Cache and temporary file age is based on modification time. Cleanup scans database text references, protecting missing-file artwork, editor originals/overlays, artwork backups, and animated stills. Active library scans defer cleanup. Media files and real catalog items are never deleted. The Hidden missing-file placeholders category removes book and episode placeholders after Show missing files has remained disabled for the retention period. Unshared artwork from removed placeholders is then eligible for the same cleanup run if its file is old enough. Expired provider and local artwork caches includes AniDB metadata and expected-episode lists older than retention. Removed-library and item sync records deletes known settings for removed libraries and orphaned item snapshots, pending edits, destination queues, and destination links. Preview reports obsolete records separately from files and bytes. Cleanup waits for server sync as well as scans; editor originals remain protected. Artwork restore history and old snapshot references are retired on upgrade; unreferenced native backup files are handled by normal artwork cleanup. Deleted-file reader data removes registrations and all users’ progress/bookmarks for files confirmed missing while their parent directory remains accessible. It runs on the next cleanup without a retention delay. Missing mounts, unavailable parent directories, and permission errors do not trigger deletion. User-wide reader appearance preferences are preserved. Other provider search caches are not removed.
- Optimize Database: SQLite quick health check, query-statistics optimization, passive WAL checkpoint. This does not run a blocking VACUUM.

Book Library Settings → Show missing files defaults on for existing and new libraries. Turning it off immediately hides missing volume/chapter/episode cards and starts the hidden-placeholder retention period. Data Cleanup can remove hidden placeholders and their unused artwork afterward. Reenabling the option before cleanup cancels that retention period. After cleanup, reenabling and scanning regenerates placeholders from known totals or cached provider episode lists; removed artwork is not restored.
